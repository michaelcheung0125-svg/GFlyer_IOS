# GFlyer 用到的「捷徑」

GFlyer 有兩件事沒辦法自己做，必須借用 iOS 內建的「捷徑」App：

| 功能 | 為什麼要捷徑 |
|---|---|
| 補錄步數 | 寫入健康 App 需要 HealthKit entitlement，免費 Apple ID 拿不到，SideStore 重簽時也會把它剝離 |
| 切換飛行模式 | iOS **完全沒有**讓 App 切換飛行模式的公開 API，私有 API 在側載環境也不可行（開、關各一個捷徑） |

兩者都不是繞過限制，而是把動作交給捷徑用**它自己的權限**執行。這也代表免費
與付費簽名帳號都能用。

總共三個捷徑：補錄步數一個，飛航開與飛航關各一個。**全部都是選用的**——不建
也能用 GFlyer，只是那兩件事要自己手動做。

---

## 捷徑一 · 補錄步數

**捷徑名稱（預設）**：`GFlyer 補錄步數`

### 建立步驟

1. 開啟「捷徑」App，按右上角 **+** 新增捷徑。
2. 搜尋並加入動作 **「記錄健康樣本」**。
3. 把類型改成 **「步數」**。
4. 點數值欄位，選 **「捷徑輸入」**——這一步最容易漏，漏了會每次都寫入固定值。
5. 重新命名捷徑為 `GFlyer 補錄步數`。
6. 在捷徑詳細資料裡關閉 **「執行前先詢問」**，否則每次補錄都要多按一次。

### 在 GFlyer 裡怎麼用

- **設定 → 補錄步數**：1000 / 3000 / 5000 或自訂步數，並可看最近七天紀錄。
- **地圖右側工具列的步行圖示**：一鍵補錄預設步數。

一鍵按鈕在捷徑**成功回報過一次之前**是灰色的，按下去會開啟設定頁而不是直接
送出。理由是：捷徑名稱打錯或動作沒設好時，直接送出只會跳到「捷徑」App 顯示
找不到，使用者不會知道要回哪裡修。成功一次之後這個判斷就永久成立，即使七天
紀錄被清掉也不會退回未設定狀態。

要改一鍵按鈕的步數，到 **設定 → 補錄步數 → 地圖上的一鍵補錄**。

### 名稱要一致

GFlyer 是用名稱呼叫捷徑的，所以**名稱必須完全一致，包含空格**。改了捷徑名稱
就要同步改 GFlyer 裡的設定，反之亦然。

## 捷徑二、三 · 飛航開 與 飛航關

**捷徑名稱（預設）**：`GFlyer 飛航開`、`GFlyer 飛航關`

### 為什麼需要

實測在**行動網絡**下，先進飛行模式再建立模擬明顯比較穩定。完整順序是：

```
開飛行模式 → 開始模擬 → 關飛行模式
```

已經建立的 CoreDevice 通道可以從飛行模式延續到行動網絡回來之後，所以第 3 步
不會中斷模擬。Wi-Fi 下通常不需要這串操作。

### 建立步驟

飛行模式只有開和關兩種，所以**建兩個捷徑，各自只有一個動作**，不需要「如果」
判斷，也不需要選任何變數。

**捷徑一（開啟）**

1. 開啟「捷徑」App，按右上角 **+** 新增捷徑。
2. 搜尋並加入動作 **「設定飛航模式」**。
3. 確認它顯示的是 **「開啟」**（預設就是）。
4. 命名為 `GFlyer 飛航開`。

**捷徑二（關閉）**

5. 再新增一個捷徑，同樣加入 **「設定飛航模式」**。
6. 點動作上的「開啟」把它改成 **「關閉」**。
7. 命名為 `GFlyer 飛航關`。

最後把兩個捷徑的 **「執行前先詢問」** 都關掉，否則每次切換都要多按一次確認。

> **為什麼不用一個捷徑加「如果」？**
> 做得到，但「如果」動作有 **Input** 和 **Condition** 兩個參數：要先點 Input
> 選「捷徑輸入」，再點 Condition 選條件。前面沒有動作時 Input 欄位不會直接
> 顯示出來，這一步實測最容易卡住。兩個各一行的捷徑沒有這個問題。
>
> 已經建好「如果」版本的人不用重建：把同一個名稱填進 GFlyer 的兩個欄位即可，
> GFlyer 仍然會把 `on` / `off` 當作文字輸入傳過去。

### 在 GFlyer 裡怎麼用

點地圖右側工具列的**飛機圖示**開啟「飛航模式輔助」。偵測到行動網絡時這個圖示
會變成橙色。

畫面上三個步驟會**自己推進**：GFlyer 用 `NWPathMonitor` 看得到網絡實際狀態，
所以你從控制中心手動切換飛行模式，畫面一樣會跟著跳。這解決的是原本最麻煩的
一點——不用再猜「現在可以關掉飛行模式了嗎」。

建好捷徑後，在該畫面開啟「用捷徑切換飛行模式」，把兩個名稱填進「開啟用」與
「關閉用」，第 1、3 步就能在 App 內一鍵完成。沒建捷徑的人畫面照樣可用，只是
那兩步要自己去控制中心切。

### 只有「關閉」會自動執行

「模擬開始後自動關閉」預設開啟，但**只作用在關閉方向**，而且只在你從輔助畫面
按「開始模擬」的那一次生效。

自動**開啟**飛行模式刻意不做：那一步若中途失敗（捷徑被改名、使用者取消、
捷徑 App 沒回來），使用者會被留在完全斷網的狀態而且不一定馬上發現。關閉方向
沒有這個風險——失敗了就是維持現狀，自己關掉即可。

## 排查

| 狀況 | 原因 |
|---|---|
| 跳到「捷徑」App 顯示找不到捷徑 | 名稱不一致。注意全形空格與前後空白 |
| 每次都要多按一次確認 | 捷徑詳細資料裡的「執行前先詢問」沒關 |
| 補錄後步數不對 | 數值欄位沒設成「捷徑輸入」，變成寫入固定值 |
| 補錄紀錄一直停在「未確認」 | 捷徑跑完沒回到 GFlyer。確認是用 GFlyer 的按鈕啟動，不是在捷徑 App 裡手動執行 |
| 飛航輔助顯示「偵測中」 | 只剩 VPN 之類的介面，判斷不出底層連線。三個步驟仍然可以直接按 |
| 一鍵切換按鈕是灰色的 | 「開啟用」「關閉用」兩個名稱都要填，少一個就不算設定完成 |

## 實作位置

- `GFlyerIOS/Services/ShortcutBridge.swift`——組 x-callback-url，兩個功能共用
- `GFlyerIOS/Services/StepRecorderController.swift`——補錄步數與七天紀錄
- `GFlyerIOS/Services/AirplaneAssistController.swift`——網絡偵測與步驟推導
- 回呼 scheme `gflyer://` 宣告在 `Info.plist` 的 `CFBundleURLTypes`，
  `canOpenURL` 需要的 `shortcuts` 宣告在 `LSApplicationQueriesSchemes`
